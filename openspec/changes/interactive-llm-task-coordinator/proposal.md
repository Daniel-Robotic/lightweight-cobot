# Proposal

## Why

Текущий стек принимает готовый graph-v3 извне, но не поддерживает задачу, заданную обычным текстом, последовательный выбор одного действия моделью и повторную оценку обновлённой сцены. Новый ROS 2 пакет должен замкнуть этот цикл внутри ROS и позволить менять JEV и совместимые модели настройками общего `cobot-setting.yaml`.

## What Changes

- Добавить пакет координатора текстовых задач, который ведёт сессию от команды пользователя до подтверждения цели или безопасной остановки.
- Добавить настраиваемый клиент LLM с `base_url`, API-ключом, именем модели и форматом API; включить OpenAI Chat Completions-совместимый адаптер и точку расширения для других адаптеров.
- После каждого успешного действия получать новый `scene_json` и состояние робота, сохранять историю задачи и запрашивать у модели ровно следующий допустимый шаг.
- Проверять выбранное действие по живому каталогу и передавать его через существующий валидируемый интерфейс `iiwa_llm_plan_executor`; не разрешать модели отправлять произвольные ROS-команды или движения.
- Определить ROS action для запуска долгой текстовой задачи, получения обратной связи и отмены, а также статусы уточнения, завершения и безопасной остановки.
- Расширить общий `cobot-setting.yaml` настройками провайдера, тайм-аутов и лимитов цикла; секреты поддержать через ссылку на переменную окружения и исключить из логов.

## Capabilities

### New Capabilities

- `llm-task-orchestration`: Текстовые задачи, модельный выбор единичных действий, состояние сессии, цикл обновления сцены, исполнение через ROS и терминальные статусы.

### Modified Capabilities

- Нет. Контракт graph-v3 и исполнитель остаются границей безопасного исполнения; координация добавляется отдельным поведением.

## Impact

- Новый Python ROS 2 пакет в `src/`, интеграция с `iiwa_scene_context`, `iiwa_llm_plan_executor` и типами `iiwa_msgs`.
- Общая конфигурация `cobot-setting.yaml`, launch/bringup, зависимости HTTP-клиента и секретов.
- Требуются контрактные и unit-тесты провайдера/цикла, а также сценарий проверки взаимодействия в Webots. Физический робот не используется для автоматической проверки.
- Корневые README и обе языковые страницы существующей MkDocs документации должны описать настройку провайдера, запуск, статусы сессии и границу безопасности.
