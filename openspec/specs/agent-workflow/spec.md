# Рабочий процесс разработки с агентами

## Purpose

Определяет единый процесс постановки, спецификации, реализации и документирования изменений Lightweight Cobot с использованием Codex, OpenCode и PolzaAI.

## Requirements

### Requirement: Спецификация предшествует реализации
Каждая задача, затрагивающая поведение, архитектуру, интерфейсы, конфигурацию или документацию проекта, MUST быть описана в OpenSpec до изменения кода. Артефакты OpenSpec для проекта SHALL быть написаны на русском языке. Спецификация SHALL включать цель, область изменения, проверяемые требования и сценарии приёмки; для задач движения также SHALL указывать единицы, систему координат, поведение при отказе и симуляционную проверку.

#### Scenario: Новая задача
- **WHEN** пользователь формулирует новую задачу в Codex
- **THEN** Codex изучает актуальную реализацию и создаёт или обновляет change в `openspec/changes/`
- **AND** реализация не начинается до появления проверяемых требований

### Requirement: Реализация через заданную модель
Codex SHALL передавать реализацию в OpenCode, используя DeepSeek V4.1 Flash 1017. Точный доступный ID модели SHALL быть `polza/deepseek/deepseek-v4.1-flash-1017`; другой вариант модели не SHALL считаться эквивалентным.

#### Scenario: OpenCode доступен
- **WHEN** OpenCode CLI доступен в окружении
- **THEN** задача реализации передаётся OpenCode с точным ID DeepSeek V4.1 Flash 1017
- **AND** передаются ссылка на OpenSpec change, границы задачи и команды проверки

### Requirement: Fallback на PolzaAI
Если OpenCode недоступен, SHALL использоваться PolzaAI с той же моделью DeepSeek V4.1 Flash 1017. Если ни один маршрут или точный ID модели недоступен, агент MUST сообщить о блокировке и не подменять модель другой.

#### Scenario: OpenCode недоступен
- **WHEN** невозможно запустить OpenCode или использовать точную модель через него
- **THEN** задача направляется в PolzaAI с ID `deepseek/deepseek-v4.1-flash-1017`
- **AND** спецификация и критерии приёмки остаются неизменными

### Requirement: Проверка соответствия спецификации
Codex SHALL проверить результат реализации по требованиям OpenSpec и фактическому diff. Пункт задачи MUST быть отмечен выполненным только после подтверждения. Основная спецификация в `openspec/specs/` SHALL быть синхронизирована с завершённым поведением.

#### Scenario: Завершение реализации
- **WHEN** реализация и проверки завершены
- **THEN** Codex сопоставляет каждое требование с изменением и результатом проверки
- **AND** обновляет основную спецификацию и состояние задач

### Requirement: README остаётся актуальным
При каждом изменении поведения, настройки, установки или процесса разработки SHALL проверяться и при необходимости обновляться `README.md` и `README_en.md` с использованием навыка `readme-authoring`. README MUST содержать только подтверждённые сведения и команды.

#### Scenario: Изменение пользовательского процесса
- **WHEN** изменение меняет быстрый старт, конфигурацию, доступные команды, интеграции или вклад в проект
- **THEN** оба корневых README обновляются согласованно

### Requirement: Актуальная документация MkDocs
Операторская и пользовательская документация SHALL поддерживаться в существующем MkDocs Material сайте `doc/lwc-doc/`. Значимые изменения настройки, запуска, интерфейсов или разработки SHALL отражаться на русской и английской страницах и в навигации MkDocs, если добавлена новая страница. Новая параллельная документационная инфраструктура MUST NOT создаваться.

#### Scenario: Документирование изменения
- **WHEN** меняются инструкции или сведения, необходимые пользователю или участнику разработки
- **THEN** соответствующие RU и EN страницы обновляются вместе с навигацией при необходимости

### Requirement: Общие навыки проекта
Проектные навыки для Codex, OpenCode и BB SHALL храниться в `.agents/skills/` в формате Agent Skills с `SKILL.md`. Происхождение и установленный commit навыков SHALL быть зафиксированы в `.agents/skills/SOURCES.md`.

#### Scenario: Добавление навыка
- **WHEN** навык добавляется или обновляется
- **THEN** он устанавливается в общий каталог, проверяется наличие `SKILL.md`, а источник и commit отражаются в каталоге источников

### Requirement: Безопасная проверка робототехнических изменений
Для изменений движения SHALL сначала планироваться проверка в Webots. Проверка физического робота MUST выполняться оператором отдельно после проверки сети, ограничений суставов, активного инструмента, Load Data, режима управления и рабочей зоны.

#### Scenario: Изменение траектории
- **WHEN** спецификация или реализация затрагивает движение робота
- **THEN** критерии приёмки включают симуляционный сценарий
- **AND** физический запуск не выполняется агентом автоматически
